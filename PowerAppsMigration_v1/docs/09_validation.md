# 9. 검증 상태와 수용 기준

## 이번 작업에서 수행한 검증과 미수행 경계
- 기존 Python/Excel은 실제 파일을 로컬로 분석했습니다. 기존 소스와 원본 Excel의 해시를 전후 비교하여 변경되지 않았는지 확인합니다.
- 변환기는 원본을 read-only로 읽고 staging 행 보존, 사용자/상세위치 매핑, 날짜 말일 계산, S/N 중복 보류, 동일 파일 재실행 키를 로컬 테스트합니다.
- 가상 20행에서 staging=20, ready=16, S/N 검토=4인지 검사합니다. 실제 이관 출력은 공개 자료 밖에 둡니다.
- Power Fx 파일은 괄호/문자열 같은 **정적 기초 검사**만 합니다. Power Fx 타입 검사·컴파일·SharePoint 위임 검증과 같지 않습니다.
- format-example.pa.yaml은 Microsoft v3 JSON Schema의 구조 검사를 수행합니다. 컨트롤/수식/앱 실행 유효성 검사와 같지 않습니다.
- HTML 시안은 가상 데이터로 브라우저 검색·메뉴·상세 열기/닫기·편집 시뮬레이션을 시험합니다. Power Apps 런타임 검증이 아닙니다.
- PnP PowerShell, Power Automate, SharePoint Lists, Power Apps Studio 가져오기/게시/테넌트 권한 시험은 이 환경에서 실행하지 않았습니다.

## Power Apps에서 반드시 통과할 기준
| 시험 | 합격 기준 |
|---|---|
| 샘플 이관 | staging 20=ready 16+보류 4. 중복/잘못된 S/N을 임의 삭제하지 않음 |
| 원본 특수 열 | Plant의 상세 위치와 사용자가 뒤바뀌지 않음. 창고 체크와 소모품이 합쳐지지 않음 |
| 날짜 | 오늘/어제/30·31/60·61/90·91일, 빈 날짜, 미취득, 1/31+1개월, 윤년 2/29+12개월 |
| 검색 | 기본 접두어와 정밀 부분 문자열의 차이가 표시되고, 복수 단어 정밀 검색이 기존 의미와 일치 |
| 위임 | 데이터 한도 1 및 2,001+ 가상 행에서도 마지막 레코드의 S/N/PC 조회 가능 |
| 대량 SharePoint | 5,000+ 규모의 선택적 필터와 OR 조회를 Monitor로 확인. 인덱스만으로 통과 선언 금지 |
| 상세/편집 | 읽기 전용으로 열림 → 수정 → 성공 때만 닫힘. 원본 값/수식은 읽기 전용 |
| 동시 쓰기 | 같은 ETag를 가진 A/B 중 A 저장 후 B는 HTTP 412. B 입력 보존 |
| S/N 경쟁 | 동시 새 등록에서 한 개만 생성. 대소문자/공백 표준화, O/0 비치환 |
| 권한 | 조회자가 직접 목록/Flow를 호출해도 수정 불가. 관리자 삭제 권한 우회 불가 |
| 저장 불확실 | 타임아웃은 미저장으로 단정하지 않고 RequestId/실제 항목으로 확인 |
| 갱신 | 상세 편집 중 자동 Refresh 보류. 조회 갱신과 편집 스냅샷 혼동 없음 |
| 정밀 조회 | 상한 초과/부분 페이지에서 Complete=false. 전체 데이터인 것처럼 표시하지 않음 |
| 카드/CSV | 서버 전체 페이지 집계/내보내기와 조건이 일치. 계산 시각·완료 여부 표시 |
| SAP | 단일 회계 시트, 추출 없는 묶음 자산 별도, 중복/폐기/유형/번호 차이 분리. 원본 불변 |
| 재가져오기 | 실제 Studio export를 새 앱/환경에 가져오고 연결/권한/Flow/목록 ID를 재검증 |
| 접근성/화면 | 키보드 모달 포커스, 스크린리더 이름, 색상 외 상태 표기, 작은 화면 입력 가능 |

실제 패키지의 완료 상태는 '작성/정적검사/Studio검사/실행시험/재가져오기시험'을 구분해서 기록합니다. 이번 결과는 로컬 개발 자료 단계입니다.
